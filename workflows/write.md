# Workflow: Write for an ordinary reader

Read `references/scenario-first.md`, `references/ordinary-writing-style.md` and the chosen template.

For `scenario-tutorial` or `problem-solution`, follow:

real problem → next action → starting material → first request → plausible first result → precise correction → useful checked result → one next use

Prompts should sound like something a person would type: “这是老师发来的通知，帮我挑出要准备的东西。看不清的先标出来，别猜。” Do not default to a role/context/task schema.

Keep one task in the article. Use one or two examples that let the reader see what to copy and what to check. Show a plausible factual miss only when the correction teaches a useful safeguard. Do not force an error into every article.

For `ordinary-person-news`, keep launch details brief, state who can access the feature and pivot to a practical task. For other types, use news only as supporting context.

Default `technical_depth=1`; see `references/technical-depth.md`. Label fictional training material. Never turn a community anecdote or sample prompt into the user's experience.

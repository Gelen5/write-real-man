# WorkBuddy 刚装好，第一句话可以这样问

“帮我写一份周报。”

这句话当然可以发给 WorkBuddy。不过，如果后面没有工作记录，它怎么知道你这周做了什么？就算交出一篇从开头到结尾都齐全的文章，里面也未必有几件事和你有关。

所以这篇教程，我们就写一份周报。从下载软件开始，写到你能打开文件，检查完后交出去。练习中的工作记录是虚构的，自己使用时，换成你这周真正做过的事。

还没安装的话，先去 [WorkBuddy 官网](https://www.codebuddy.cn/work/) 选适合电脑的版本。Windows 用户下载后双击安装包，跟着提示安装。打开客户端，点击登录，在浏览器里完成微信扫码等登录操作，看到成功提示后回到客户端。具体页面可以对照[官方 Windows 安装指南](https://www.codebuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Installation-Win-Guide)。

现在到输入框里，把手头的记录贴进去。没整理过也没关系，原始材料可以是这样的：

> 周一修改活动海报，周二发给同事确认，对方还没回复。周三整理了客户提出的几个问题。原定周五交方案，目前只写完大纲，下周一继续。

这里有已经做完的事，也有正在等别人回复的事，还有没按时交的方案。先把这些情况留下，别忙着自己润色。

接着，在同一条消息后面加上：

> 根据上面的记录写一份给直属领导看的周报，分成已完成、待确认和下周安排。用普通的工作语言，300 字以内。没有提到的成果和数字不要补。方案目前只有大纲，请如实写出进度。

你也可以写得更随意一点，比如“就照这些事整理，别替我加业绩”。但“给谁看”和“写到什么程度”最好说明白。给领导的周报需要交代进度，发给搭档的消息可能只需要告诉对方海报还差一次确认，两份内容不用写成一样。

先发一次看看。假如 WorkBuddy 给你的是下面这版：

> 本周已完成活动海报修改及确认，整理并解决了客户反馈问题。项目方案正在顺利推进，预计下周完成。

读着挺顺，实际情况已经被改了。海报还没人回复，客户问题只是收拢到一起，方案也只写到大纲。直接把原始进度补回去：

> 海报还在等同事回复，放到“待确认”里。客户问题只是整理完了，没有解决。方案目前只有大纲，下周一继续写。请按这三个事实修改，别加“顺利推进”。

改完以后，把新版本和最初那四句记录放在一起看。海报应该还在等回复，客户问题没有凭空多出处理结果，方案也没有提前完成。少了哪件事，就告诉它少了什么；哪句话写过了，就把那句话贴回去改。

如果它问“方案为什么延期”，而你手头没有确定说法，可以回：

> 延期原因先不写，我还没有确认。周报里只保留“目前完成大纲，下周一继续”。

写到这里，正文就差不多了。接着发一句：

> 把刚才确认的版本保存成“本周周报.md”。正文不要再改，保存后告诉我完整路径。

`.md` 是 Markdown 文本文件。保存完成后，到右侧结果区找“本周周报.md”。官方快速开始把这里称为结果区，可以查看产物、文件和预览。[官方快速开始](https://www.codebuddy.cn/docs/workbuddy/Quickstart)

文件出现以后，先打开，搜索“确认”“解决”“顺利推进”这几个词。它们如果还在，就回到刚才那条修改意见继续改。聊天窗口里的版本已经正确，而文件里还是旧内容，也要让它重新保存；最后交出去的是文件，不是聊天记录。

公司有固定周报格式的话，下一次把空白模板和工作记录一起交给它。某个栏目没有内容，就写“无”或者先留空。到了下周五，把新的几句工作记录换进去，仍然先看事实有没有被写大，再保存文件。

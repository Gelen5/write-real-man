# Technical explanation when explicitly requested

Use this reference only when the user wants engineering or model detail, or when one technical fact is required to explain the ordinary task.

- Keep the user's question in view; do not switch to a general technology survey.
- Name the mechanism accurately, then explain what changes for the reader.
- Use primary documentation for claims about APIs, models, versions and product behavior.
- Explain a term only when it unlocks the next decision or action.
- Separate documented facts from inference and state meaningful limits.
- Prefer one concrete example over a catalog of adjacent concepts.
- Do not use engineering jargon to make a simple task sound consequential.
